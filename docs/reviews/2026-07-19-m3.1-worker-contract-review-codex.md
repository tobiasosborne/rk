LANDING-BLOCKERS

1. **BLOCKER — Driver-owned provenance is accepted from untrusted worker output.** `docs/worker-contract.md:95`, `docs/worker-contract.md:166`, `schemas/verdict.v1.json:14`, `schemas/verdict.v1.json:27`, `src/drive/verdict-schema.ts:147`.  
   **Failure scenario:** a worker returns a structurally valid but false `itemId`, `contentHash`, `tier`, `batchId`, `modelFamily`, or `sessionId`. The validator returns `[]`; the wrong node can be promoted, batch provenance can be lost or fabricated, stale-on-edit can be bypassed, and cross-vendor provenance can be forged. The contract calls these fields “driver-supplied,” but places them in the worker-supplied document.  
   **Resolving change:** split raw worker output from the driver-enriched verdict artifact. The driver must inject identity, batch, tier, item ID, and hashes from immutable dispatch state—or compare every echoed value for exact equality—before constructing and validating the downstream verdict document. Reject missing, extra, duplicate, or mismatched items atomically.

2. **MAJOR — Role/claim isolation is prose-only and `claimId` is absent from the request.** `docs/worker-contract.md:34`, `docs/worker-contract.md:57`, `docs/worker-contract.md:69`.  
   **Failure scenario:** a verifier request resumes a prover session, or a session for another claim, while still satisfying the documented request shape. Nothing binds `sessionId` to `(backend/model, role, tier, claim)`.  
   **Resolving change:** add `claimId` and `turnId`; maintain an immutable driver-side session record keyed by at least `(backend, model, role, tier, claimId, dispatchModel)`. Validate every resume against it. A flat backend must reject resume mode and receive a fresh synthetic attempt/session ID.

3. **MAJOR — The singular-turn request conflicts with unbounded, mixed-tier responses.** `docs/worker-contract.md:78`, `docs/worker-contract.md:99`, `schemas/verdict.v1.json:20`, `test/drive/verdict-schema.test.ts:95`.  
   **Failure scenario:** one hard-tier item is dispatched, but the response contains forty verdicts, duplicate item IDs, or mixed L5/hard outcomes. The tests explicitly ratify mixed tiers; `verdicts: []` also validates. A direct probe confirmed all these shapes return no issues.  
   **Resolving change:** under the session/one-item-per-turn model, require exactly one verdict per call (`minItems: 1`, `maxItems: 1`) and require its item/tier to match the request. The batch cap then limits turns per claim, not verdicts in one reply.

4. **MAJOR — `contentHash` does not pin which bytes are hashed.** `docs/worker-contract.md:78`, `schemas/verdict.v1.json:138`.  
   **Failure scenario:** dispatch hashes the rendered `item.content`, while M3.7 later recomputes raw shard-file bytes—or hard-tier code compares af’s canonical node hash. All are SHA-256-shaped but have different domains, causing false freshness or permanent false staleness. Af’s hash is specifically over a canonical concatenation of node fields, not prompt bytes.  
   **Resolving change:** define hash domains byte-for-byte: L5 should use raw shard-file bytes with no normalization; hard tier should use af’s recorded `content_hash` algorithm/value. Identify the domain explicitly and verify the current source hash both before dispatch and before apply. If the full verification input must stale on dependency/rubric changes, add a separate canonical `inputHash`.

5. **BLOCKER — `modelFamily` can falsely satisfy the cross-vendor rule.** `docs/worker-contract.md:177`, `schemas/verdict.v1.json:30`, `test/drive/verdict-schema.test.ts:15`, `test/drive/verdict-schema.test.ts:48`.  
   **Failure scenario:** the same OpenAI model can be recorded as family `codex` in one verdict and `gpt` in another—the tests demonstrate both conventions—so plain inequality reports false cross-vendor independence. `codex` is a backend/product, not a model lineage. Vibefeld V1 stores only free-text `author`/`validated_by`, and no canonical serialization from this structured identity to those strings is defined.  
   **Resolving change:** make family a driver-registry value, never model output. Use one namespace of actual lineages/vendors; remove `codex`. Remove `other` or replace it with registered canonical family IDs. Define lossless, canonical encoding into Vibefeld V1—or extend that seam structurally—so M3.8 can recover both author and verifier families without parsing arbitrary strings. Literal `other != other` is false, which is conservatively safe, but `other` cannot distinguish future families and `other` versus a named alias can still produce a false promotion.

6. **MAJOR — Verdict labels lack downstream transition semantics.** `schemas/verdict.v1.json:71`, `schemas/verdict.v1.json:87`, `schemas/verdict.v1.json:118`.  
   **Failure scenario:** M3.7 may promote `VALID-WITH-CORRECTION` although no correction is structured or applied. Likewise, a hard `challenge` with nonblocking severity `minor`/`note` does not specify whether this turn also validates the node. Different consumers can make opposite validity decisions from the same valid document.  
   **Resolving change:** normatively define each outcome’s state transition. Require structured correction detail for `VALID-WITH-CORRECTION` and forbid promotion until the corrected bytes are re-bound as specified. State whether every hard `challenge` means “not accepted this turn,” regardless of severity, or introduce an explicit accept-with-advisory-challenge shape.

7. **MAJOR — The response envelope and partial-delivery contract are inconsistent.** `docs/worker-contract.md:95`, `docs/worker-contract.md:112`, `schemas/verdict.v1.json:6`.  
   **Failure scenario:** the documented `WorkerResponse` contains `usage` and `exit`, but the schema instead requires `schema_version` and `verifier` and would reject `usage`/`exit` as extra properties. If a valid verdict is streamed before malformed output, timeout, budget failure, or process crash, the contract does not explicitly prevent early application.  
   **Resolving change:** define one normalized envelope and whether the authoritative exit is the process code or wrapper result. Buffer a complete turn; apply only after process success, full parsing, schema validation, and contextual binding. On failure, discard every verdict from the current call. Previously completed turns remain committed; the failed and undispatched items remain unapplied and are reported explicitly.

FOLLOW-UPS

1. `docs/worker-contract.md:170` states the honesty limit correctly—“driver-supplied, recorded and mechanically checkable, not adversary-proof”—but the wire design currently contradicts it as described in blocker 1. Also state that nonblank justification is only structurally checked; `"OK"` passes and substantive per-item reasoning is not mechanically established.

2. `docs/worker-contract.md:133` overattributes the stagger details to measurement. One asymmetric concurrency pair was measured; “await first streamed token,” universal race behavior, and “no escape” were not. Keep the conservative stagger rule, but distinguish measured observation from policy/provider-derived assumptions.

3. `docs/worker-contract.md:139`’s three-item floor is a pricing-derived recommendation, not a measured three-item batch result. It is sound as a scheduling heuristic if described that way.

4. `docs/worker-contract.md:144`’s 4,096-token threshold was documented background, not measured by the spike, and is model-specific. Attribute it accordingly.

5. `docs/worker-contract.md:148` measured that the Claude flag changes and shrinks the prefix. Cross-host stability is a reasonable inference, not a measured multi-host result.

6. `docs/worker-contract.md:155` measured use of the `ephemeral_1h` tier and survival across 180 seconds, not the actual expiry boundary. Do not promise cache survival for scheduling arbitrarily close to one hour.

7. `docs/worker-contract.md:160`’s ban on re-sending context is sensible, but repeating context on a resumed turn was not tested directly; the flat-prompt experiment does not prove identical resume behavior.

8. The mirrored severity and category bytes currently match Vibefeld exactly. Add a cross-repo seam fixture so future enum drift cannot silently pass.

9. The new validator is not represented in the red corpus despite guarding validity failures. The unit suite is green—68/68 targeted, 1182 pass/1 skip overall, selftest 109/109—but it tests structural corruption rather than request/response binding.

Verdict: **not sound to merge as v1 now; sound after List 1 is repaired and mechanically verified.** Open-question rulings: **Q1:** Codex defaults to `dispatchModel:"flat"` until a Codex-specific spike proves continuation semantics; do not infer them from Claude. **Q2:** use structured integer token limits on the worker wire, not an ambiguous scalar or dollars; keep dollar campaign budgets and versioned price conversion driver-side. **Q3:** retries belong to the shared driver, with caps/backoff in config; adapters perform one attempt, and ambiguous timeout retries require a new session or idempotent `turnId`, never blind resume. **Q4:** a second JSON Schema is unnecessary while requests are internal, but TypeScript types alone are insufficient—add runtime request/session invariant validation and property tests; add a schema if requests become a serialized plugin boundary. **Q5:** cap each session turn at exactly one verdict; the batch cap limits turns. Forced decisions: **RATIFY** session/turn dispatch for batching, with explicit non-cache-credited flat fallback; **REJECT as combined** the “≥3 floor + 1h TTL scheduling” decision as written—ratify the ≥3 economic floor, but only record an observed 1h tier and 180-second survival, not a measured expiry guarantee; **RATIFY** byte-for-byte Vibefeld challenge vocabulary; **REJECT** the exact closed `modelFamily` enum—retain closedness after removing backend/catch-all ambiguity and defining canonical family identity.
