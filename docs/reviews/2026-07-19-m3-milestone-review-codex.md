## LANDING-BLOCKERS

1. **BLOCKER — Verdicts are not bound to the bytes ultimately accepted.** `src/drive/driver-run.ts:195-200,255-263`; `src/drive/l5-dispatch.ts:85-112`. The hard-tier driver trusts the pre-dispatch content hash and does not re-read the af node before applying; L5 can dispatch `deps.content` while recording an unrelated `member.contentHash`. An edit during the model turn—or a stale caller—can therefore validate unreviewed content. Compute the hash from the exact dispatched bytes, then re-read and re-hash the authoritative source immediately before apply/append; discard the turn on any mismatch.

2. **MAJOR — Challenge and empty-frontier states can be reported as successful convergence.** `src/drive/driver-run.ts:229-231,263-271`. af reports a successfully recorded challenge as `status: "applied"`; the driver counts it as progress, and later returns `converged` merely because no node is verification-ready. A challenged root can therefore produce a successful campaign result without an accepted proof. Count only accept events as validation progress, give challenges a non-success/repair-required outcome, and require the current root to be validated before returning `converged`.

3. **MAJOR — The apply path accepts verdicts from roles other than verifier and does not implement genuine per-node hard-tier treatment.** `src/drive/driver-run.ts:188-210,255-263`; `src/drive/driver-guardrails.ts:46-64`. A `reviewer` identity passes the overreach check and can mint an af acceptance. Additionally, all ready nodes share one identity/session and one V2 batch apply, despite `batchEligibleIds` being empty; every acceptance receives batch provenance. Require `role === "verifier"` exactly. In current per-node mode, use one verifier claim/session and one non-batch apply per af node; only an actual composed batch may share a session and `batch_id`.

4. **MAJOR — Codex can apply output from an incomplete or discarded turn.** `src/drive/backend-codex.ts:34-49,130-138`. Malformed/truncated event lines are skipped and exit zero is accepted without requiring a terminal `turn.completed`; a plausible output file from an incomplete execution can reach the ledger. Require exactly one valid successful terminal event, reject failure/error or missing completion, and read the verdict output only afterward.

5. **MAJOR — M3.8’s grandfathering and critical-path boundary are gameable.** `src/gates/linker-crossvendor.ts:74-76,92-95,113-137`; `src/drive/cross-vendor.ts:54-67`; `src/drive/batch-composer.ts:166-177`; `docs/gate-contracts.md:604-620`. Unparseable identities become legacy warnings, so a new same-family result can evade enforcement by using free text. The legacy token uses substring matching, critical-path batch provenance is only a warning, and an unresolved north star yields an empty critical set that permits every batch. Make unparseable identity an ERROR unless an exact explicit legacy token is present; compare atomic provenance tokens; make post-cutover critical-path batch provenance an ERROR; and fail closed when the configured north star cannot be resolved. The apply-time fail-closed behavior itself is correct.

6. **MAJOR — Corrupt or stale L5 history can still promote—or remain promoted.** `src/drive/l5-store.ts:40-47,127-148`; `src/drive/l5-store-io.ts:76-92`; `src/gates/linker-l5.ts:54-79`. Malformed tail records are skipped, duplicate/out-of-order ordinals are not rejected, and the writer appends through reported corruption. An earlier VALID can consequently survive a later truncated INVALID. The linker also checks only `status: stated`, so a previously promoted shard can remain `proved-mod-audit` after editing, INVALID, or correction-pending. Treat any parse, ordinal, hash, or chain issue as poisoning promotion; refuse append through corruption; and continuously validate or demote already-promoted shards.

7. **MAJOR — Repeat-balloon routing is not durable.** `src/drive/driver-run.ts:151-163`; `src/drive/driver-balloon.ts:83-88`; `src/graph/from-registry.ts:54-72`. First missing-fact and DAG-dependency events create bd work but do not persist the balloon count/classification. The next event can therefore remain “first” indefinitely. Registry projection also hard-codes `balloons: 0`, so the linker/board cannot surface the state. Atomically persist every classified balloon before routing it, parse the counter/classification into the graph, and surface mandatory-review state through the linker/board.

8. **MAJOR — SC4 accounting can materially overstate savings.** `src/drive/report.ts:148-159,211,222-253`; `src/drive/backend-types.ts:70`; `src/drive/l5-dispatch.ts:82-112`; `src/cli/verify.ts:141-147`. Baselines are joined using non-unique bare af node IDs; duplicate, negative, and fractional baseline entries are accepted; driver-log parse issues are dropped from the report; session-creation usage and all L5 usage are absent. This can undercount current spend and fabricate a favorable ratio. Record session creation and L5 usage, key baseline rows by registry claim/contract identity, require unique non-negative integer values, and make comparison unavailable when input has parse or attribution errors. Evenly amortizing cache creation within a session is otherwise acceptable.
