## LANDING-BLOCKERS

1. **MAJOR — A node can claim af-backed proof without carrying any af evidence.** [schemas/graph.v1.json:125](</home/tobiasosborne/Projects/rk/.claude/worktrees/agent-a4bba59283c06ac65/schemas/graph.v1.json:125>), [validate.ts:34](</home/tobiasosborne/Projects/rk/.claude/worktrees/agent-a4bba59283c06ac65/src/graph/validate.ts:34>), [validate.ts:84](</home/tobiasosborne/Projects/rk/.claude/worktrees/agent-a4bba59283c06ac65/src/graph/validate.ts:84>). A node with `status:"proved"`, `af:"validated"`, and a workspace but no `edges.af` validates with zero issues. Likewise, `resolved:true` is accepted with no `contractMatch`, epistemic state, taint state, schema version, or node count. A renderer therefore has no machine-required evidence preventing an unsupported green/proved presentation. Require exactly one af edge for every node with `af != "none"`. Make the edge a discriminated union: unresolved workspace requires a bucket entry; resolved workspace requires af schema version, root-node identity, contract-match verdict, enumerated epistemic/taint states, and node count.

2. **MAJOR — Contract matching is explicitly allowed against a non-root af node.** [schemas/graph.v1.json:136](</home/tobiasosborne/Projects/rk/.claude/worktrees/agent-a4bba59283c06ac65/schemas/graph.v1.json:136>), [types.ts:109](</home/tobiasosborne/Projects/rk/.claude/worktrees/agent-a4bba59283c06ac65/src/graph/types.ts:109>). A registry contract can match an internal lemma in an unrelated workspace while that workspace’s root states something different; the edge may then report the child’s validated/clean state and support a false `proved` presentation. The gate contract requires the af root statement. Require the unique root node—currently node `1`, or structurally the node without `parent_id`—and byte-match against that entry’s `statement`, never `workspace.conjecture` or an arbitrary descendant. Rename `afNodeId` to `afRootNodeId` or otherwise encode this invariant.

3. **MAJOR — Contradictory proof state can validate with an empty conflict list.** [schemas/graph.v1.json:132](</home/tobiasosborne/Projects/rk/.claude/worktrees/agent-a4bba59283c06ac65/schemas/graph.v1.json:132>), [schemas/graph.v1.json:137](</home/tobiasosborne/Projects/rk/.claude/worktrees/agent-a4bba59283c06ac65/schemas/graph.v1.json:137>), [validate.ts:170](</home/tobiasosborne/Projects/rk/.claude/worktrees/agent-a4bba59283c06ac65/src/graph/validate.ts:170>). The contract for `resolved` contradicts itself: one description says it implies a contract match, while another permits `resolved:true, contractMatch:false`. A `proved` node paired with `pending`, `tainted`, and `contractMatch:false`, but `conflicts:[]`, validates cleanly. Separate this into `workspaceResolved` and mandatory `contractMatch`; make epistemic and taint values closed enums; close the four known conflict kinds; and have validation recompute the known conflicts so missing, duplicate, or inconsistent conflict records are errors. The fr shape must also retain enough banked/oracle-verdict freshness data to compute `banked-without-oracle`.

4. **MAJOR — Distinct unresolved fr references collapse, and resolved fr edges need not target a node.** [validate.ts:118](</home/tobiasosborne/Projects/rk/.claude/worktrees/agent-a4bba59283c06ac65/src/graph/validate.ts:118>), [validate.ts:139](</home/tobiasosborne/Projects/rk/.claude/worktrees/agent-a4bba59283c06ac65/src/graph/validate.ts:139>). Completeness is keyed only by `(edge, ref)`. Two unresolved cycles naming the same artifact are satisfied by one bucket entry for only the first cycle; both validate cleanly. A resolved fr edge pointing to `lem-ghost` also validates cleanly. Key fr unresolved entries by `(edge, sourceCycle, ref)`, require `sourceCycle` for fr, enforce exact one-to-one accounting, and check `resolvedNodeId` referential integrity. Also forbid `resolvedNodeId` on unresolved edges and record every source reference attempt so a reader cannot omit an entire unresolved cycle invisibly.
