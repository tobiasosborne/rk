## af — easy direction, confirmed

Every one of the 44 `proofs/<name>` workspaces AISM's registry declares via `workspace:` resolved
against a REAL `af export --graph json --dir <path>` invocation (not the direct-ledger fallback —
`afSchemaVersion` reads `"1"` on all 44, confirmed by inspecting the assembled document directly).
Epistemic states seen: `pending`, `validated`. Taint states seen: `unresolved`, `clean`. Zero
contract byte-mismatches between a registry shard's `contract` and its af workspace's root
`statement`.

## fr — hard direction, measured honestly

**8.0% is a genuine baseline, not a red flag.** Breaking down the 185 unresolved refs by shape:

| category | count | share |
|---|---|---|
| `docs/waves/...` narrative wave documents — episodic research notes, never registry shards | 112 | 60.5% |
| `proofs/<id>/...` where `<id>` IS a real, CURRENT registry id (e.g. `proofs/lem-classical-equiv/export.md`) | 33 | 17.8% |
| `runs/...` bundle docs — same shape as wave docs, no registry counterpart | 18 | 9.7% |
| assorted (`docs/lit-review/*`, `docs/recon/*`, `docs/plans/*`, `report/sections/*.tex`, two orchestrator-scratchpad paths, one stale workspace name — see "Oddities" below) | 22 | 11.9% |

fr's `evidence.artifact` overwhelmingly cites SUPPORTING documents (wave narratives, run bundles,
literature notes) rather than the registry's own `argument/lemmas/*.md` shard path or bare id —
exactly the free-text, unvalidated-reference hazard PRD C5 and `../knowledge-frontier/docs/
export-v1.md`'s "Hazards for the M2.2 reader" section both name explicitly ("fr does not validate
[`evidence.artifact`] against anything real"). The 8.0% rate reflects that reality, not a resolver
defect: `validateGraphDocument` reports 0 issues, and the unresolved bucket accounts for all 185
entries exactly (never dropped, never double-counted).

The `proofs/<id>/...` row (33 entries, 17.8%) is the one genuinely actionable gap: `M2.2`'s
resolver only tries an EXACT match against a node's `path` or bare `id` (PRD C5's stated join
keys); it does not additionally try "does this ref's `proofs/<workspace>/...` prefix match a
node's `workspace` field." That would be a natural, low-risk resolution-method addition — **not
built in this WP** (scope discipline: the brief specifies path/id/graduated_to resolution, not a
prefix heuristic) — filed as a follow-up, not silently added.

- **`conj-halo-collapse`** appears in one fr `evidence.artifact` (`proofs/conj-halo-collapse/

- Two unresolved refs name an orchestrator-session scratchpad path (`/tmp/.../scratchpad/w53`,
  `.../w54/...`) — a transient path that was never going to resolve against any registry shard;
  correctly bucketed as unresolved rather than causing a crash or a false match.
- No crash, no silent skip, anywhere across the 200-shard / 44-workspace / 433-record / 178-line
  read.
